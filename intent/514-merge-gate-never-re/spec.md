# Spec: Auto-Resolution of Transient Conjunct (2) Merge Gate Declines

**Issue:** #514 · **Status:** Approved (approval = merge of this PR) · **Author:** athena (`evekhm-athena-app[bot]`) · **Open questions:** none

## What is being built

Under this repository autonomous development lifecycle, `scripts/ci/merge_gate.sh` executing from `.github/workflows/merge-gate.yml` evaluates eleven conjuncts to determine whether a pull request merges unattended.

The merge gate currently evaluates once upon receiving a trigger event and never re-evaluates automatically. When a decline is caused by a transient condition, the pull request remains stranded indefinitely in a declined state. When a reviewer posts a review comment, that comment triggers the gate within seconds while the reviewer workflow run (or infrastructure workflow jobs such as `resolve`) is still `IN_PROGRESS` or `QUEUED`.

Measured production incidents demonstrate this defect:
1. Pull Request #512 (Build rung of #508, 2026-09-17): Argus posted its review comment at 17:33:24Z, triggering the gate 4 seconds later at 17:33:28Z. The gate read `argus=IN_PROGRESS` in `statusCheckRollup` and declined on conjunct (2). All other conjuncts were true, including reviewer consensus and loop ledger checks. The pull request sat stranded for 3 hours and 28 minutes until an operator manually reran the gate without code or comment changes, whereupon all checks evaluated green and the pull request merged at 21:01:46Z.
2. Pull Request #515 (Implement rung of #508, 2026-09-17): Reviewer posted review while `resolve` was `QUEUED`. The gate declined on conjunct (2). Within one minute, every check on the commit head reached `SUCCESS`. The pull request sat stranded until an operator triggered a manual rerun.

This failure breaks unattended operation silently: it emits no red CI check on the commit, posts no alert comment on the pull request, and leaves pull request labels indicating readiness to merge. Only manual operator log audits recover stranded pull requests.

This specification establishes mechanical auto-resolution of transient conjunct (2) declines:
1. **In-Gate Bounded Polling Wait:** When conjunct (2) encounters foreign checks in transient states (`IN_PROGRESS`, `QUEUED`, `PENDING`, `WAITING`, `REQUESTED`) or `mergeStateStatus: UNKNOWN` while all other merge preconditions hold, `scripts/ci/merge_gate.sh` polls check status with bounded retries before issuing a final verdict.
2. **Precondition Gating (Anti-Resource-Waste):** The in-gate polling wait executes if and only if all other merge conjuncts (1, 3, 4, 5, 6, 7, 8, 9, 10, 11) evaluate true. If any non-conjunct-(2) precondition is false, the gate declines immediately without polling.
3. **Immediate Abort on Terminal Failure (Fail-Fast):** If any check transitions to a terminal failure state (`FAILURE`, `CANCELLED`, `TIMED_OUT`, `ACTION_REQUIRED`, `STALE`, `STARTUP_FAILURE`), or `mergeStateStatus` transitions to a terminal state (`DIRTY`, `BLOCKED`, `DRAFT`), the polling loop terminates immediately and declines.
4. **Configurable Bounds and Zero-Delay Testing:** Polling timeout ceiling (`MERGE_GATE_TRANSIENT_TIMEOUT`, default 120 seconds) and polling interval (`MERGE_GATE_TRANSIENT_POLL_INTERVAL`, default 5 seconds) are configurable via environment variables. Setting either to 0 executes polling checks with zero sleep delay, ensuring fast, deterministic contract tests.
5. **Diagnostic Logging:** Clear logging distinguishes in-flight timeouts from terminal check failures and merge state issues.
6. **Living Documentation:** `docs/SPEC.md` is updated to describe the in-gate transient check polling loop and configuration variables.

## Acceptance

- **AT-514-1 (D1):** In-flight check polling resolution. When foreign check runs are initially in an in-flight state (`IN_PROGRESS` or `QUEUED`) while all other conjuncts hold, `scripts/ci/merge_gate.sh` polls and, upon checks transitioning to `SUCCESS`, evaluates conjunct (2) true and merges the pull request.
  - *Red input:* A check that stays in `IN_PROGRESS` without transitioning to `SUCCESS` causes conjunct (2) to fail and prevents merging.
- **AT-514-2 (D2):** Precondition gating prevents polling when other conjuncts fail. When conjunct (4) fails due to an open blocking finding, but a foreign check is `IN_PROGRESS`, `scripts/ci/merge_gate.sh` declines immediately without polling and does not execute any sleep loops.
  - *Red input:* A runner that polls despite open blocking findings causes poll execution logs or delay to appear, turning this assertion red.
- **AT-514-3 (D3):** Immediate abort on terminal failure. When a foreign check transitions to `FAILURE` or `CANCELLED` during polling, `scripts/ci/merge_gate.sh` aborts polling immediately without waiting for remaining in-flight checks, reports conjunct (2) false, and declines.
  - *Red input:* Continuing to poll until the timeout ceiling after a check has failed causes elapsed poll iterations to exceed 1, turning this assertion red.
- **AT-514-4 (D4):** Timeout ceiling enforcement. When an in-flight check remains in `IN_PROGRESS` through the timeout ceiling, `scripts/ci/merge_gate.sh` exits the polling loop, reports conjunct (2) false with a timeout diagnostic, and declines.
  - *Red input:* An infinite polling loop that does not terminate upon reaching `MERGE_GATE_TRANSIENT_TIMEOUT` causes a hang, turning this assertion red.
- **AT-514-5 (D4):** Zero-sleep configuration override. Executing `merge_gate.sh` with `MERGE_GATE_TRANSIENT_POLL_INTERVAL=0` and `MERGE_GATE_TRANSIENT_TIMEOUT=0` completes polling logic and timeout evaluation with zero sleep delays.
  - *Red input:* Hardcoded non-zero sleep calls cause execution duration to exceed 1 second when interval is set to 0, turning this assertion red.
- **AT-514-6 (D5):** Diagnostic categorization in gate log. When an in-flight check times out, the gate output log carries `check(s) in flight timed out after` naming the timed-out check; when a check fails terminally, the log carries `check(s) not success:`.
  - *Red input:* Emitting identical log strings for both terminal failure and timeout causes the specific timeout assertion to fail.
- **AT-514-7 (D6):** Living specification update in `docs/SPEC.md`. `docs/SPEC.md` contains the updated conjunct (2) text describing bounded in-flight check polling, timeout bounds, and configuration variables. `bash scripts/ci/spec_check.sh` passes.
  - *Red input:* Omitting the conjunct (2) update from `docs/SPEC.md` causes `scripts/ci/spec_check.sh` or living spec verification to fail.
- **AT-514-8 (D7):** Scope boundary enforcement. The diff of the implementing PR touches only permitted files (`scripts/ci/merge_gate.sh`, `scripts/ci/tests/merge_gate_test.sh`, `docs/SPEC.md`, `CHANGELOG.md`, `intent/514-merge-gate-never-re/*`). No files under `.github/workflows/*`, `personas/**`, or `config/**` are modified.
  - *Red input:* Modifying `.github/workflows/merge-gate.yml` in the diff causes this check to exit 1.
- **AT-514-9 (D7):** Changelog entry. `CHANGELOG.md` contains an entry documenting auto-resolution of transient conjunct (2) merge gate declines, and `bash scripts/ci/changelog_check.sh` passes.
  - *Red input:* Omitting the changelog entry causes `scripts/ci/changelog_check.sh` to exit 1.
