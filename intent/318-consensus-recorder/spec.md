# Spec: Anchored Verdict Marker Parsing and Loud Declines in Consensus Recorder

**Issue:** #318 · **Status:** Approved (approval = merge of this PR) · **Author:** athena (`evekhm-athena-app[bot]`) · **Open questions:** none

> [!NOTE]
> Notation: Every marker in this document is written with bracketed notation (such as `[review-verdict:<reviewer>:<verdict>]` or `[reviewed-head:<sha>]`) where real comments emit HTML comment syntax. This ensures the document cannot be parsed as live verdict input by existing unanchored recorder parsers.

## What is being built

The consensus recorder (`scripts/ci/review_recorder.py`) parses structured review verdict blocks and finding rows using unanchored, non-greedy regular expressions over comment bodies. On pull request #316, this unanchored matching allowed quoted text from an intent document to pair with a later closing marker, causing author mismatch refusal and swallowing real Argus findings. Furthermore, on pull request #317, interactively dispatched rounds carrying `run-id:0` caused the recorder to decline unprovenanced findings silently, leaving a ledger that appeared clean while findings were omitted.

This specification hardens the consensus recorder and merge gate across five architectural areas:

1. **Anchored Marker Parsing and Structure Exclusion (D1)**: In `scripts/ci/review_recorder.py`, all verdict markers (`review-verdict`, `reviewed-head`, `run-id`, `round`, `finding`, `failure-scenario`, `review-verdict-end`) must begin at line start (`^[[:space:]]*[marker]`). Lines inside fenced code blocks (delimited by triple backticks or triple tildes), indented code blocks (indented by 4 spaces or a tab), and markdown blockquotes (`>`) are ignored during marker extraction.
2. **Author-to-Reviewer Binding Prior to Block Matching (D2)**: In `scripts/ci/review_recorder.py`, the expected reviewer is derived directly from the comment author login (`evekhm-argus-app[bot]` maps to `argus`; `evekhm-atlas-app[bot]` maps to `atlas`). The parser searches solely for opening markers matching the authenticated reviewer (`[review-verdict:{reviewer}:...]`). Comments authored by non-reviewer accounts are skipped for verdict block parsing. Quoted markers naming a different reviewer cannot initiate a block.
3. **Loud Declines Across All Decline Paths (D3)**: When a comment contains an unparseable, malformed, or author-mismatched verdict block, `review_recorder.py` logs an attributed audit note and calls `record_refusal(...)`, emitting a machine-readable refusal marker `[refused-verdict:<reviewer>:<reviewed_head>:<reason_code>]` inside the consensus ledger block. Specifically, author mismatches emit `author-mismatch` refusal markers.
4. **Merge Gate Row Comparison and Ledger-Blindness Detection (D4)**: In `scripts/ci/merge_gate.sh`, Conjunct (3) inspects pull request comments for reviews targeting `$HEAD` from assigned reviewers (`argus`, `atlas`). The gate compares posted finding rows (`[finding:<fid>:...]` outside code blocks and quotes) against recorded ledger rows (`CTUP`). If a posted finding at `$HEAD` has no ledger counterpart and carries no recorded refusal marker, Conjunct (3) evaluates false with: `WHY[3]="ledger blindness: reviewer <reviewer> posted finding <fid> at $HEAD with no ledger counterpart"`.
5. **Anchored Maintainer Retier Directives (D5)**: The maintainer retier directive scanner in `scripts/ci/review_recorder.py:278` is anchored to line start outside fenced code blocks and blockquotes: `^[[:space:]]*@(argus|atlas)\s+retier\s+([A-Za-z0-9@-]+)\s+([a-zA-Z0-9]+)[[:space:]]*$`. Quoted instructions or prose cannot trigger finding severity changes.
6. **Tracked Artifact Marker Sanitization Gate (D6)**: `scripts/ci/sanitize_check.sh` introduces a fourth scan rule, `marker`. Tracked repository files outside test fixtures and entries in `scripts/ci/sanitize_allowlist.txt` must contain zero unescaped live verdict markers. Documentation and intent artifacts must use bracketed notation when referencing markers.
7. **Immutable Historical Ledgers (D7)**: Existing consensus ledger comments on merged pull requests are immutable. Historical defect exposure is validated through contract test fixtures in `scripts/ci/tests/review_recorder_test.sh` and `scripts/ci/tests/merge_gate_test.sh`.
8. **Living Specification Synchronization (D8)**: `docs/SPEC.md` is updated during implementation under `### review.recorder` and `### review.policy`.
9. **Implementation Scope Boundaries (D9)**: The implementation is confined to CI scripts, documentation, and contract tests.

| **D1** | **Line-start marker anchoring and markdown structure exclusion.** In `scripts/ci/review_recorder.py`, structured review verdict markers (`review-verdict`, `reviewed-head`, `run-id`, `round`, `finding`, `failure-scenario`, `review-verdict-end`) must begin at line start (`^[[:space:]]*[marker]`). The recorder strips or ignores lines inside markdown code fences (triple backticks or tildes), indented code blocks (indented by 4 spaces or a tab), and markdown blockquotes (`>`) prior to matching verdict spans. | *Adversary analysis:* Two defensible readings: (1) Strip all fenced code blocks, indented code blocks, and blockquotes in a pre-processing pass before matching blocks; (2) Process comments line-by-line while maintaining state machine flags for code fences. Differing case: A comment quotes an Atlas verdict block inside a blockquote (`> [review-verdict:atlas:clean]`) followed by an authentic Argus findings block outside quotes. Under Reading 1, stripping blockquoted lines removes the quoted block prior to regex evaluation. Under Reading 2, multi-line regular expressions require complex span arithmetic to exclude quoted inner blocks. Reading 1 is selected for deterministic parsing simplicity and robustness against multi-line regex poison. |
| **D2** | **Author-to-reviewer binding before verdict block matching.** In `scripts/ci/review_recorder.py`, the consensus recorder binds the expected reviewer directly from the comment author login (`evekhm-argus-app[bot]` maps to `argus`; `evekhm-atlas-app[bot]` maps to `atlas`). The recorder searches solely for opening markers matching the authenticated reviewer (`[review-verdict:{reviewer}:...]`). Comments authored by logins outside authorized reviewers are not parsed for review verdict blocks. | *Adversary analysis:* Two defensible readings: (1) Search for any reviewer opening marker in the comment body, then compare the matched reviewer against the author login; (2) Bind the expected reviewer from the comment author login first, searching solely for that reviewer opening marker. Differing case: An Argus review comment quotes an Atlas clean verdict block (`[review-verdict:atlas:clean]`) and concludes with an Argus closing marker (`[review-verdict-end]`). Under Reading 1, non-greedy matching pairs the quoted Atlas opening marker with the Argus closing marker, flags an author mismatch, and swallows authentic Argus findings. Under Reading 2, the parser searches only for `review-verdict:argus:`, ignores the quoted Atlas marker, and successfully records the Argus verdict. Reading 2 is selected. |

Differing case: A comment posted by an unauthenticated login attempts to publish a verdict block for commit `$HEAD`. Under Reading 2, the gate identifies the explicit `author-mismatch` refusal marker and surfaces an informative diagnostic. Reading 2 is selected. |

## Acceptance

- **AT-318-1 (D1):** A review comment authored by `evekhm-argus-app[bot]` containing an example verdict block inside markdown fenced code blocks or blockquotes (`> [review-verdict:argus:clean]`) followed by an authentic findings block outside code blocks records only the authentic findings block; the quoted block is ignored.
- **AT-318-2 (D1):** An unanchored marker mid-line (such as `Text [review-verdict:argus:clean]`) is ignored by the consensus recorder and does not open a verdict block.
- **AT-318-3 (D2):** A comment authored by `evekhm-argus-app[bot]` containing quoted text with `[review-verdict:atlas:clean]` followed by an Argus findings block does not match the Atlas marker; the Argus findings block is parsed and recorded.
- **AT-318-4 (D2, D3):** A comment authored by an unauthorized login containing a line-anchored `[review-verdict:argus:clean]` block fails author validation, logs an attributed audit note, and emits `[refused-verdict:argus:<head>:author-mismatch]` into the consensus ledger block.
- **AT-318-5 (D3):** A verdict block containing a malformed or missing reviewed-head emits an attributed refusal audit note and a corresponding machine-readable refusal marker in the consensus block.
- **AT-318-6 (D4):** When an authorized reviewer posts finding `R1-1` for `$HEAD` in a pull request comment, and the consensus ledger carries zero findings and no refusal marker for that reviewer at `$HEAD`, `merge_gate.sh` evaluates Conjunct (3) to false and sets `WHY[3]` containing `ledger blindness: reviewer`.
- **AT-318-7 (D4):** When all posted findings for `$HEAD` match recorded ledger rows in `CTUP`, or when an explicit refusal marker is recorded, `merge_gate.sh` does not trigger the ledger-blindness diagnostic.
- **AT-318-8 (D5):** Quoting `@argus retier R1-1 normal` within a markdown blockquote or code block, or preceded by text on the same line, does not alter the severity of finding `R1-1`.
- **AT-318-9 (D5):** A line-anchored `@argus retier R1-1 normal` outside code blocks by an authorized collaborator successfully retiers finding `R1-1`.
- **AT-318-10 (D6):** Running `scripts/ci/sanitize_check.sh` on a tracked file containing an unescaped live verdict marker outside `scripts/ci/sanitize_allowlist.txt` fails with exit status 1 and reports the location.
- **AT-318-11 (D6):** `bash scripts/ci/sanitize_check.sh` passes with exit status 0 when all documentation files use bracketed marker notation.
- **AT-318-12 (D8, D9):** `bash scripts/ci/tests/review_recorder_test.sh`, `bash scripts/ci/tests/merge_gate_test.sh`, and `bash scripts/ci/tests/sanitize_check_test.sh` exit 0.
