# Spec: a live view of who owns which issue, at which rung

**Issue:** #68 · **Status:** Approved (approval = merge of this PR) ·
**Author:** athena (`evekhm-athena-app[bot]`) ·
**Open questions:** none

## What is being built

A single read-only command, `scripts/ops/board.sh`, that inspects the repository and prints the live join across issue labels, claim comments, open pull requests, git branches, local worktrees, and harness sessions. It answers "who owns what, at which rung, and where is it running" for every issue in flight without requiring subsequent queries, while remaining strictly read-only toward GitHub and maintaining zero drift from `scripts/ops/work.sh`.

```text
scripts/ops/board.sh             # the live board implementation (gather, correlate, render)
scripts/ops/lib/github.sh        # gh_json query parameter fix (? vs & separator for pagination)
scripts/ops/tests/board_test.sh   # hermetic test suite with stubbed gh and zero-write assertion
docs/SPEC.md                     # ops.board capability entry and docs.structure section update
README.md                        # "See who is doing what" section and two-action sentence clarification
```

`scripts/ops/work.sh`, `scripts/ops/claim.sh`, `personas/**`, and `.github/workflows/**` are **not** touched (D10).

## Acceptance

Every row is checkable deterministically without a model call in `scripts/ops/tests/board_test.sh`:

- **AT-1 (D1, D4): In-flight issue rendering.** Open issues carrying `status:*` or `in-progress` render under `IN FLIGHT` with issue number, stage, title, and flags, sorted newest activity first.
- **AT-2 (D7): Structured claim resolution.** For an in-progress issue, the author of the last comment opening with `Claim:` (or bold `**Claim:`) is identified as the holder; comments mentioning "claims" in prose are ignored.
- **AT-3 (D8): Stage and claim mismatch.** An issue on `status:planning` held by `odyssey` renders `mismatch: claimed by odyssey, but stage plan is owned by athena`.
- **AT-4 (D8): Mutex without structured claim.** An issue carrying `in-progress` with no structured claim comment renders `in-progress set but no structured Claim comment: the mutex names nobody`.
- **AT-5 (D8): Corrupt multi-status labels.** An issue carrying two `status:*` labels renders `CORRUPT: two status labels` and does not derive a stage.
- **AT-6 (D4): Intake separation.** An issue carrying only `intent:new` without `status:*` is excluded from `IN FLIGHT` and rendered under `INTAKE waiting`.
- **AT-7 (D8): Released claim reporting.** An issue with a status label but no `in-progress` whose thread contains a past claim renders `unclaimed (last claim was <actor>, <age> ago; released)`.
- **AT-8 (D9): PR correlation and stack detection.** An open PR targeting another PR's head branch renders `stacked on <base> (#<parent_pr>)`, checks failure renders `CHECKS FAILING`, and conflicts render `CONFLICTS`.
- **AT-9 (D7): Operator-bot proxy attribution.** A comment posted by `evekhm-odyssey-bot` on behalf of a persona is attributed to that persona marked `(via evekhm-odyssey-bot)`.
- **AT-10 (D4): Selective issue filtering.** Invoking `board.sh --no-fetch 102` renders only the block for issue #102 and suppresses all other issue blocks.
- **AT-11 (D3, D11): Zero GitHub writes.** Across all test assertions, the stub `$WRITES` log remains empty, proving no mutating calls or unexpected API methods were executed.
- **AT-12 (D6): Default one-shot execution.** Invoking `board.sh --no-fetch` completes a single pass and exits 0 without looping.
- **AT-13 (D5, D10): Scope boundary and spec compliance.** The implementing PR diff touches only the five files listed in D10, and `scripts/ci/spec_check.sh origin/main <pr-body>` exits 0.
- **AT-14 (D7): Case-insensitive claim matching.** A claim comment opening with `claim:` or `Claiming` matches identically to `work.sh`'s regex without error on null comment bodies.

## Out of scope

- **History of a single issue (#71 `ops.trace`).** The board presents the current state across all issues; `ops.trace` tracks the chronological history and audit trail of one issue.
- **Autonomous acting on state (#64).** The board displays state to human operators; automated dispatching or merging is handled by the autonomous loop.
- **Reviewer verdicts as machine state (#8, #9).** Review aggregation beyond GitHub review states (`APPROVED`, `COMMENTED`, `CHANGES_REQUESTED`) is handled by review consensus automation.
- **Modifying dispatcher or claim mechanics.** `scripts/ops/work.sh` and `scripts/ops/claim.sh` remain untouched.
- **Automated remediation of corrupt states.** The board highlights contradictions; it does not attempt to clear labels or apply `hold`.
