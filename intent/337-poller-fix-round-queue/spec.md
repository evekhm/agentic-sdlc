# Spec: Poller Fix-Round Queue Resolves PR to Issue for Multi-Rung Stage Verification

**Issue:** #337 · **Status:** Approved (approval = merge of this PR) · **Author:** athena (`evekhm-athena-app[bot]`) · **Open questions:** none

## What is being built

This specification resolves issue #337 by repairing the VM poller's fix-round queue (`scripts/placement/vm-local/poll.sh`) and dispatch handling (`scripts/ops/work.sh`) to support automated fix rounds across builder rungs (spec PRs by Athena, plan PRs by Daedalus, and implement PRs by Odyssey).

In the current implementation:
1. `poll.sh` queries open pull requests with `--label status:in-review` and asserts that candidate PRs carry `status:in-review`. However, pull requests in this repository never carry `status:*` labels (the lifecycle state machine is maintained solely on the underlying tracking issue by `lifecycle_advance.sh`).
2. Even on the tracking issue, `status:in-review` is written only when an implementation PR merges, advancing the issue to the terminal review rung. While any builder PR is open and under review, its tracking issue carries the stage label corresponding to that rung:
   - Spec PR: issue carries `status:spec`
   - Plan PR: issue carries `status:build`
   - Implement PR: issue carries `status:implementing`
3. As observed empirically on PR #335 (spec PR for issue #308), when Atlas posted a blocking `high` finding, `poll.sh` found 0 candidate PRs because of the non-existent `status:in-review` filter, leaving the PR blocked until manual operator intervention.
4. In `scripts/ops/work.sh:399`, `is_fix_round` detection required `[ "$status_labels" = "status:in-review" ]`, which similarly blocked non-implement PR fix rounds and caused branch/slug mismatches.
5. In `scripts/ci/tests/e2e_chain_test.sh`, tests AT-13, AT-20, and AT-21 used synthetic fixtures where PR objects carried artificial `status:in-review` labels, masking this bug in CI.

This specification:
1. Removes `--label status:in-review` from `poll.sh` section 2, excludes draft PRs (`--draft=false`), and queries all open repository pull requests with fields `number,title,labels,headRefName,headRefOid,isCrossRepository,isDraft`.
2. Sources `scripts/ops/lib/github.sh` in `poll.sh` and defines `die() { echo "poll.sh: $*" >&2; exit 1; }` adhering to `github.sh:13`.
3. Implements deferred PR-to-issue resolution within an isolated subshell wrapper: `poll.sh` checks the reviewer trigger predicate (blocking findings by Argus or Atlas) and consumption key first. Only when an unconsumed blocking review finding exists does `poll.sh` invoke `resolve_issue "$pr_num"` inside the subshell. If `gh` fails or resolution encounters an error, `die()` exits with code 1 in the subshell, leaving the parent supervisor process unharmed. `poll.sh` tests the subshell exit status before inspecting variables; if non-zero, it logs a skip notice, leaves the dispatch key unwritten, and advances to the next candidate PR.
4. Enforces fail-closed tracking issue validation: the resolved tracking issue must be open (`state == "open"` in `$ISSUE_JSON`), must not carry circuit breakers (`hold` or `blocked`), and the PR itself must not carry `hold`.
5. Caches terminal refusals (closed tracking issue, `status:review-stuck`, or stage mismatch) using a negative refusal key `${poll_state_dir}/refuse-pr-${pr_num}-${repo_hash}-${head_oid}`, skipping re-evaluation until the PR head commit changes. Transient refusals (`hold`, `blocked`) write no refusal key, permitting immediate dispatch on the subsequent tick once the label is lifted.
6. Enforces strict stage-to-author alignment before dispatching across builder rungs:
   - `athena`: resolved issue must carry `status:spec` (stage `design`).
   - `daedalus`: resolved issue must carry `status:build` (stage `build`).
   - `odyssey`: resolved issue must carry `status:implementing` (stage `implement`).
   If the stage fails to match the author persona, `poll.sh` logs a skip notice, writes a negative refusal key for the current head commit, and skips dispatch.
7. Harmonizes `is_fix_round` in `scripts/ops/work.sh` so that any PR authored by a builder persona (`athena`, `daedalus`, `odyssey`) dispatched with `--as "$pr_head_author"` on an issue at the author's stage sets `is_fix_round=1`, preserving the PR's exact branch slug (`pr_head_slug`). For legacy compatibility when `status_labels == "status:in-review"`, `stage` is set to `implement`; otherwise `stage` retains the stage derived from the issue's labels.
8. Updates contract tests AT-13, AT-20, and AT-21 in `scripts/ci/tests/e2e_chain_test.sh` to remove `status:in-review` from PR fixtures, provide realistic tracking issue fixtures, test subshell failure handling against failing `gh` reads, test terminal refusal caching, and add multi-rung test coverage for Athena (spec PR) and Daedalus (plan PR).
9. Updates the living specification (`docs/SPEC.md`).

- **AT-3 (Daemon-Safe Subshell Error Handling):** In `poll.sh`, when `gh` fails on the initial PR read (`issues/<pr_num>` exits 1), or when a candidate PR links multiple issues, `resolve_issue` invokes `die()` which exits 1 in the subshell; `poll.sh` detects the non-zero exit status, logs `poll.sh: skipping PR #$pr_num (could not resolve to tracking issue)`, touches no `key_file`, and continues execution with the daemon process surviving (derives from D3).

## Concerns

- **API Rate Limiting and Caching Arithmetic:** `poll.sh` section 2 evaluates open builder pull requests on a 30-second interval. For candidate PRs without a cached refusal key, `poll.sh` fetches PR comments (`gh api .../issues/<pr_num>/comments`), costing 1 API call per tick per candidate PR (approximately 120 calls per hour, well within GitHub token ceilings of 5,000 requests per hour for personal access tokens and 15,000 per hour for GitHub Apps). Deferring PR-to-issue resolution ensures `resolve_issue` is invoked only when an unconsumed blocking review finding exists. Terminal refusals (closed tracking issue, `status:review-stuck`, or stage mismatch) write a negative refusal key keyed on the PR head commit SHA (`head_oid`), cutting repeated resolution and comment fetches for stuck PRs to zero on subsequent ticks until new commits are pushed. Transient refusals (`hold`, `blocked`) omit negative keys to permit instant resume upon label removal.
- **Daemon Resilience and Subshell Isolation:** `poll.sh` runs continuously under supervisor / systemd. Sourcing `scripts/ops/lib/github.sh` requires fulfilling its contract that `die()` exits non-zero. Confining `resolve_issue` execution within a subshell wrapper ensures that library exits terminate only the subshell. The parent `poll.sh` daemon inspects the subshell return status, logs unresolvable PRs, and continues uninterrupted.
- **Key and Lock Cleanup:** Fix-round lock files, dispatch keys, and negative refusal keys reside in `POLL_STATE_DIR`. The existing PID liveness checks and 2-hour staleness threshold in `poll.sh:200-222` protect against abandoned locks.
