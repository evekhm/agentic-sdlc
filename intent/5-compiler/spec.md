# Spec: the persona compiler (scripts/sync_agents.py)

**Issue:** #5 · **Status:** Approved (approval = merge of this PR) ·
**Open questions:** none

Bootstrap compression per intent/1-personas/spec.md D10 applies:
planning artifacts and implementation land in one PR, recorded once,
not a precedent.

## What is being built

```text
scripts/sync_agents.py            the build: personas/ + config/ -> targets
scripts/ci/compiler_roundtrip.sh  the proof, in six checks
.claude/agents/<name>.md          compiled Claude Code targets (committed)
.agents/agents/<name>/            compiled Antigravity targets (committed)
  agent.json config.yaml instructions.md
```

Five stages, per persona x per harness: **load + validate** every
`personas/*.yaml` against `personas/schema.json`; **resolve**
tier→model, persona→harness, capability→tools from `config/`;
**assemble** one instruction body; **emit** through one emitter per
harness; **sanitize** before any byte reaches disk.

## Decisions

| ID | Decision |
|----|----------|
| D1 | The build is pure and deterministic: no timestamps, no machine state, no network, no ordering that depends on filesystem iteration. Sources are processed sorted by name; emitted mappings use sorted keys. Two consecutive builds are byte-identical, which is what makes the #6 drift gate a plain rebuild-and-diff. |
| D2 | Emission targets follow the deployment pin: a `kind: persona` source is emitted ONLY for the harness it is pinned to in `config/deployments.yaml`; a `kind: subagent` source is emitted for EVERY harness, because sub-agents carry no pin and inherit their dispatcher's harness (#2, D3). |
| D3 | The instruction body is assembled once and is identical across harnesses, in fixed order: role contract → skills inlined verbatim in declared order → authority and bounds → execution caps and escalation grade → pointer to AGENTS.md → generated capability fallbacks. Only the fallback section can differ between harnesses, and only because a fallback exists exactly where a harness lacks a tool. |
| D4 | Fallback text is GENERATED from the `fallback` field in `config/tools.yaml` for optional capabilities the target harness cannot map. A REQUIRED capability with no mapping is a build failure, never a silent omission. Fallbacks are never hand-written into a target. |
| D5 | Prose in the body is hard-wrapped to 72 columns deterministically; skill files are inlined VERBATIM and unwrapped, so the roundtrip can assert the full skill text survived compilation byte for byte. |
| D6 | The Claude frontmatter `description` is derived from the role's first sentence, extended by whole sentences only while the result is under 60 characters — so a terse opener ("The product owner.") still says something useful in an agent picker. Deterministic, and derived: never authored separately. |
| D7 | Every emitted file carries the marker `GENERATED by scripts/sync_agents.py — edit personas/, not this file`. In Claude agent markdown the marker is the first line INSIDE the YAML frontmatter, because that harness requires `---` at byte 0; in `agent.json` it is the `_generated` key; elsewhere it is the first line. The marker is also the compiler's ownership record: on rebuild, marked files under the target directories that no source emits are pruned, and unmarked files are left alone. |
| D8 | Sanitize before write: the compiler refuses to emit any file whose content or path matches a home path (absolute or `$HOME`-relative), a known token shape, a private-key block, or an inline credential value. All-caps secret NAMES (`ATHENA_BOT_TOKEN`) are deliberately allowed — declaring the name is the point (#1, D6). A refusal is a build failure and writes nothing at all: the filesystem is untouched until the entire build has passed. |
| D8a | Site-specific strings (a local account name, an internal domain) are supplied at RUN time through `SYNC_AGENTS_DENY`, a comma-separated deny list, and are never committed. Hard-coding the literal you are hiding into a public repository is the leak it was meant to prevent; the generic home-path rule already catches where such a name actually appears. |
| D9 | Three modes, one script. Default builds; `--check` rebuilds and diffs against the committed targets without touching them (exit 1 on drift — the #6 gate); `--verify` re-parses the emitted targets FROM DISK and asserts each carries its resolved model, its mapped tools, and the full text of every declared skill. `--root`/`--out` compile an alternate source tree into an alternate output tree, which is how the roundtrip tests a throwaway persona without dirtying the working tree. |
| D10 | Dependencies stop at stdlib + pyyaml + jsonschema. Adding a harness is adding one emitter class and one column in `config/`; it touches zero persona sources. |
| D11 | The launcher (`run_persona.sh`) is out of scope and lands with #8/#10. This issue ends at compiled, committed, verified targets. |

## Acceptance

- `python3 scripts/sync_agents.py` compiles all 11 sources into 30
  target files: 9 Claude agent files (4 pinned personas + 5
  sub-agents) and 7 Antigravity agent directories (2 pinned personas
  + 5 sub-agents).
- `python3 scripts/sync_agents.py --check` exits 0 against the
  committed targets, and exits 1 with a per-file drift report when a
  source or a pin changes without a rebuild.
- `bash scripts/ci/compiler_roundtrip.sh` exits 0, covering: schema
  check, determinism (two builds diffed), no drift, re-parse of every
  emitted target, a throwaway persona compiled end-to-end in a temp
  tree (pinned harness only, generated fallback for an optional
  unmapped capability), a sanitizer refusal that writes nothing, and a
  run-time `SYNC_AGENTS_DENY` refusal.
- A home-path and token-shape grep over the emitted targets returns
  nothing (the sanitizer's own rules, run independently).
- `personas/` is unchanged by this PR.
- `docs/SPEC.md` gains `personas.compiler` in the same PR (the
  living-spec upsert rule).
